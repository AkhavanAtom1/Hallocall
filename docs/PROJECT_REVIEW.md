# مرور دو پروژه اولیه و تصمیم‌های نسخه نهایی

## پروژه اول — build-discord-clone-app
نقاط قوت اصلی: مدل داده کامل‌تر برای Friendship / Room / Participant / Signal / Chat / Call Invite، رابط تماس پرجزئیات‌تر، و طراحی نئونی قوی.

محدودیت اصلی برای این محصول: تکیه بیشتر روی PostgreSQL/Drizzle و polling برای بخشی از realtime؛ بنابراین برای معماری ساده‌تر Cloudflare باید بازطراحی می‌شد.

## پروژه دوم — echocall
نقاط قوت اصلی: login/register تمیزتر، ساختار صفحه‌های اصلی ساده‌تر، و جریان احراز هویت سرراست‌تر.

محدودیت اصلی: منطق تماس و realtime به اندازه سناریوی تماس گروهی نهایی کامل نبود و برای Cloudflare به همان شکل قابل استقرار بهینه نبود.

## نتیجه ادغام
در HalloCall نسخه نهایی:

- تجربه ورود و داشبورد از الگوی UI تمیز پروژه دوم الهام گرفته شد.
- مدل Friendship / Invite / Call از منطق قوی‌تر پروژه اول بازطراحی و ساده‌سازی شد.
- polling دیتابیس برای signaling حذف و WebSocket + Durable Object جایگزین شد.
- PostgreSQL/Drizzle به D1 منتقل شد تا deployment یکپارچه روی Cloudflare انجام شود.
- اتاق تماس اکنون تا ۲۰ شرکت‌کننده را با سقف ثابت Durable Object پشتیبانی می‌کند؛ سیگنالینگ همچنان WebSocket است و مسیر صدا WebRTC P2P باقی می‌ماند.
- کنترل bitrate صدا، TURN آماده، presence، incoming call، chat، reaction، mute و speaking indicator به تجربه نهایی اضافه شد.

## مرور و اصلاحات تکمیلی

- نوار بالای ورود، صفحه‌های کاربری و اتاق تماس حالا شش پالت رنگی دارد؛ انتخاب‌ها مستقل از روشن/تاریک و در مرورگر ذخیره می‌شوند. تم «مخصوص» ترکیب امضای چهاررنگ HalloCall است.
- در ساخت PeerConnection، درخواست signaling زودرس دیگر به‌دلیل آماده‌سازی ICE دور انداخته نمی‌شود؛ درخواست‌های هم‌زمان همان promise را منتظر می‌مانند و ساخت اتصال پس از خروج از اتاق باطل می‌شود.
- رد دعوت سریع، هم رکورد تماس فعال را پایان می‌دهد و هم به Durable Object اطلاع می‌دهد؛ پیش‌تر اگر میزبان زودتر وارد اتاق شده بود تماس می‌توانست باز بماند.
- برای WebSocket، مبدأ مرورگر با میزبان درخواست بررسی می‌شود تا اتصال cross-origin ناخواسته رد شود؛ هدرهای forwarded در dev proxy هم پشتیبانی می‌شوند.
- ثبت درخواست دوستی در خود دستور SQL، هر دو جهت رابطه را اتمیک بررسی می‌کند؛ ارسال هم‌زمان دو درخواست متقابل دیگر دو رابطه تکراری نمی‌سازد.
- smoke test محلی روی Worker و D1 مسیر ثبت‌نام/پروفایل/نشست، درخواست دوستی هم‌زمان، جست‌وجوی SQL با `_` لفظی، دعوت تماس، ورود میزبان و پایان تماس پس از رد دعوت را بررسی کرد.
- اعتبارسنجی ساخت نهایی با `npm run verify` (TypeScript و build) و `git diff --check` انجام می‌شود.

## مرور دوم: تم‌های شاد، تم پیش‌فرض «مخصوص» و اصلاحات

**تم‌ها**
- پنج تم شاد جدید اضافه شد: آفتابی، آبنباتی، استوایی، کارناوال و بهاری. هر کدام چهار نور رنگی، دکمه‌های با کنتراست کافی برای برچسب سفید و `--theme-ink` مخصوص حالت روشن دارند.
- منوی تم در نوار بالا به سه گروه «اختصاصی»، «شاد و پرنور» و «کلاسیک» تقسیم شد و اگر بلند شد اسکرول می‌خورد.
- «مخصوص» پیش‌فرض شد. رنگ‌های آن هر حدود ۰.۶ ثانیه به‌روز می‌شوند و یک چرخه حدود ۴۲ ثانیه طول می‌کشد (`src/lib/specialPalette.ts`). این تنها انیمیشن رنگی برنامه است و با `prefers-reduced-motion` خاموش می‌شود.
- لایه‌های نور پس‌زمینه برای همهٔ تم‌ها چهار رنگ دارند و لبهٔ بالایی کارت‌های شیشه‌ای یک درخشش رنگی گرفت.
- رنگ‌های ثابت بنفش در حالت روشن (`refinement.css`) با `--theme-ink` جایگزین شدند تا با تم انتخابی هماهنگ باشند.

**اشکال‌های رفع‌شده**
- متن کارت «بازهٔ کیفیت صدا» به شکل «kbps ۹۶-۱۲» نمایش داده می‌شد؛ حالا «۱۲ تا ۹۶ kbps» است.
- تشخیص صحبت در تماس برای هر شرکت‌کننده یک حلقهٔ `requestAnimationFrame` دائمی داشت؛ حالا تایمر ۱۲۰ میلی‌ثانیه‌ای است.
- هر درخواست API (حتی polling ۱.۵ ثانیه‌ای فهرست دوستان و دعوت‌ها) یک `UPDATE` روی `users.last_seen_at` می‌زد؛ حالا فقط وقتی مقدار بیشتر از ۱۰ ثانیه قدیمی باشد نوشته می‌شود. پنجرهٔ آنلاین ۲۰ ثانیه‌ای بدون تغییر است.
- README به فایل `.github/workflows/deploy.yml` اشاره می‌کرد که در ریپو وجود ندارد و تعداد تم‌ها را اشتباه گفته بود؛ اصلاح شد.
- اسکریپت اولیهٔ `index.html` فهرست تم‌های قدیمی را داشت؛ با فهرست جدید و پیش‌فرض «مخصوص» هماهنگ شد.

**باقی‌مانده (پیشنهاد برای مرحلهٔ بعد)**
- rate limiting برای ورود، ثبت‌نام و جست‌وجو هنوز اضافه نشده است.
- هر پاسخ ورود/ثبت‌نام جدول‌ها را با `CREATE TABLE IF NOT EXISTS` بررسی می‌کند؛ می‌توان این کار را به health check و migration منتقل کرد.
- فونت‌ها از Google Fonts بارگذاری می‌شوند و در محیط بدون اینترنت خطای شبکه می‌دهند؛ برای استقرار عمومی مشکلی نیست.
